HiveMind

Autonomous AI coding agents on Kubernetes.
Ticket in, merge request out.

K8s Native Ephemeral Pods LLM-Driven

Local coding agents sit inside one person's editor and vanish when the tab closes. HiveMind gives them an infrastructure: a queue, an orchestrator, ephemeral pods, and a review lifecycle — so agents run unsupervised, in parallel, across multiple repositories, with built-in feedback loops and zero state leakage between tasks.

The Problem with Local Coding Agents

Single-user
Only the person at the keyboard can steer the agent.
Agents pick tickets from a shared queue. Anyone on the team submits work.
No isolation
Agent edits your working tree, conflicts with uncommitted changes.
Each task gets its own ephemeral K8s pod with a fresh workspace.
No queue
You run one agent session at a time, manually.
Orchestrator manages a work queue with N parallel agent slots.
No retry
Agent fails, you re-prompt by hand.
Failed pods detected, tickets re-queued with retry context. Up to 3 automatic retries.
No review loop
Agent pushes a branch, you review later, manually tell it what to fix.
MR review comments trigger automatic follow-up sessions.
Single repo
Most agents operate in one repo at a time.
One ticket spans multiple repos — the LLM picks which ones, the agent works across all.
No observability
You watch the terminal. Walk away, you lose context.
Web dashboard, live SSE events, per-ticket logs, MR tracking — all in the browser.
No persistence
Agent learning dies with the session.
Memory blocks (persona, preferences, conventions) survive across sessions. LeanKG indexes persist on PVC.

Key Components

Orchestrator

FastAPI server (Python 3.11) as a K8s Deployment

  • Queue Processor — assigns idle agents to queued tickets, smart repo-affinity selection
  • Workspace Builder — LLM-powered ticket analysis, repo selection, prompt generation, pod spawning
  • Review Lifecycle Monitor — watches MRs for pipeline failures, merge conflicts, review comments
  • Agent Pod Monitor — tracks pod health, retry with configurable delay (3 retries, 120s)

Agent

opencode-ai (Node.js 22) in ephemeral K8s Pods

  • Phase 1 — reads assignment prompt, starts opencode web (port 4096), runs opencode run
  • Phase 2 — commits, pushes to feature/{TICKET_ID}, creates MR via @gitbeaker/rest
  • Phase 3 — polls for review comments, runs follow-up sessions to address feedback
  • Memory — per-agent persistent blocks (persona, preferences, conventions), journaling

Init Container

Clones selected repos and runs leankg init + leankg index before the main agent container starts, so the agent has full code knowledge from the first prompt.

Kubernetes Architecture

HiveMind runs entirely on Kubernetes — no external dependencies beyond your GitLab and LLM endpoint.

Agent Pod Lifecycle

apiVersion: v1
kind: Pod
metadata:
  name: agent-worker-{ticket-id}
  namespace: hivemind
spec:
  restartPolicy: Never                    # Ephemeral: runs once, then terminates
  volumes:
    - name: workspace                     # emptyDir: shared between init + main
    - name: repos-config                  # ConfigMap: repos.json
    - name: task-prompt                   # ConfigMap: assignment.md
    - name: opencode-config               # ConfigMap: opencode.json
    - name: memory-blocks                 # ConfigMap: agent memory (persona, etc.)
  initContainers:
    - name: clone-repos                   # git clone + leankg init/index
  containers:
    - name: opencode-agent               # entrypoint.sh → opencode run → push → MR
      ports:
        - containerPort: 4096            # opencode web server (interactive)
      resources:
        requests: { cpu: 500m, memory: 1Gi }
        limits:   { cpu: 4,    memory: 8Gi }
✓
Success
Pod terminates, ticket marked completed, pod deleted
↻
Failure
Pod crashes, ticket re-queued (up to 3 retries, 120s delay)
⏳
Stale
Pod gone >60 min, auto-complete and cleanup

RBAC (Least Privilege)

The orchestrator ServiceAccount can only create/update/patch/delete/get/list ConfigMaps and Pods in the hivemind namespace, and get/list pod logs. Agent pods have zero K8s RBAC — they cannot access the API server, cannot list pods, cannot read secrets beyond what is mounted into their filesystem.

Getting Started

Configure — setup.sh

An interactive script that collects all configuration values and stores them as a K8s Secret. Reads defaults from .env so you only enter values once.

./setup.sh

What it does:

  1. Checks prerequisites — kubectl installed, cluster reachable
  2. Creates the hivemind namespace if it doesn't exist
  3. Prompts for configuration with defaults from .env: GITLAB_HOST, GITLAB_TOKEN, OLLAMA_HOST, OLLAMA_MODEL, OPENCODE_MODEL, AGENT_IMAGE...
  4. Creates the orchestrator-env K8s Secret with all values
  5. Syncs entered values back to .env so subsequent runs use your answers as defaults

Build & Deploy — redeploy.sh

The single command for versioning, building, and deploying HiveMind. Handles the full pipeline: semver bump, Docker build, K8s secret update, image import, manifest apply, rollout wait, and git tagging.

./redeploy.sh              # patch bump + build + deploy

Step by step:

  • Version — reads .version, bumps (default: patch), or uses --version X.Y.Z
  • Docker build — builds hivemind-opencode + hivemind-orchestrator, tags with version + latest
  • K8s secret update — reads .env, patches orchestrator-env so agents always use latest config
  • Image import — docker save + ctr -n k8s.io images import on each worker node — makes local images available on RKE2/k3s without a registry
  • Manifest apply — kubectl apply -k Orchestrator/kustomize/base/
  • Rollout wait — kubectl rollout status with 120s timeout
  • Git commit + tag — auto-commits and tags the release
FlagWhat it does
--minorBump minor version (0.x.0)
--majorBump major version (x.0.0)
--version 2.0.0Use an explicit version
--no-cacheClean build: remove all old images first
--skip-buildOnly re-deploy the current version (no rebuild)
--dockerBuild via docker-compose instead (local testing)
--tagCreate a git tag without deploying
--changelogShow git log since the last tag

Access the Web UI

kubectl port-forward -n hivemind deployment/orchestrator 8080:8080

Open http://localhost:8080 — dashboard with 3 idle agent slots.

Submit a Ticket

Via the Web UI (Kanban board), via GitLab webhook, or via API:

curl -X POST http://localhost:8080/api/tickets \
  -H "Content-Type: application/json" \
  -d '{"id":"PROJ-123","title":"Fix login on mobile","description":"...","labels":["bug"],"priority":"High"}'

Watch the Agent Work

# Follow agent pod logs
kubectl -n hivemind logs -f agent-worker-proj-123

# Or access the opencode web UI on the agent pod
kubectl port-forward -n hivemind agent-worker-proj-123 4096:4096

The agent analyzes the codebase using LeanKG, makes changes, commits to feature/PROJ-123, pushes, creates a Merge Request, and waits for your review feedback.
